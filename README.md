# 反诈局中局：你的手机

面向大学生的竖屏 H5 反诈互动游戏。**产品形态：整个网页模拟一部可自由探索的虚构手机**；手机端直接铺满可见网页，开场、桌面、消息、钱包、结局及复盘都在手机内进行。玩家可以随时切换应用、查看余额和手册，再返回当前剧情，不强制困在对话中；电脑端居中预览同一画面。

当前状态：**多关卡结构，三关可玩**（Vue 3 + Vite + TypeScript）。

- **第一关「刷单返利」**：剧情引擎、整页手机界面、按经历复盘与版本化存档已完成。
- **第二关「冒充客服退款」**：完整可玩，金额口径 800 → 600 → 300。
- **关卡大厅**：一关一部手机，玩家自行选择；每关进度各自保留。首次进入先展示作品封面与玩法说明。当前采用**书桌版**：三台手机平放在墨绿桌垫上，点一部就**旋转放大覆盖全屏**进入那一关。轮播版已归档在 git 历史中。
- **手机必备与生活应用**：桌面有**电话**（拨号盘/最近通话/通话界面）、**短信**（收件箱/会话/本机回复）两个必备应用，以及**青集商城**（商品/搜索/订单）、**青听音乐**（切歌/播放/进度）、**青影**（抖音式竖屏 feed：上下滑动、点赞/评论/收藏/分享）三个虚构应用；不接真实通话、短信或支付服务；青影接入本地反诈视频，青听音乐接入本地完整音频，抖音头像可跳转官方主页。第二关的订单核验会从聊天切到商城的订单页，当前验证码会出现在短信应用里，银行卡/账户信息放在钱包。
- **移动端保护**：页面锁定视口、禁止下拉刷新；关卡开始后刷新/关闭会弹浏览器离开确认，进度仍由每次操作即时落盘。
- **真实案例**：反诈手册内置 4 条带来源的案例（电商退款/航班理赔/冒充公检法/刷单），来源与原文摘录只在本地开发资料中保留，游戏内不放外链。
- **第三关「冒充公检法」**：完整可玩，金额口径 800 → 300（资金核查 500）→ 0（保证金 300）。

账号、后端、排行榜均未开发。

## 命令与运行方式

```bash
npm install          # 安装依赖
npm run dev          # 本地开发（http://127.0.0.1:5173/）
npm run build        # 生产构建，输出 dist/
npm run preview      # 预览构建产物（http://127.0.0.1:4173/）
npm run typecheck    # vue-tsc 类型检查
npm test             # 单元 + 集成测试（vitest）
npm run verify       # 真实浏览器（Edge/Chrome headless）端到端验证，产出截图与报告
npm run smoke:public -- <公网URL>   # 公网部署冒烟测试：真实浏览器打开公网地址，确认能玩
```

部署：`vite.config.ts` 使用 `base: './'` 相对路径，`dist/` 可直接放到任意静态目录（含子路径）。核心剧情不依赖任何外部服务。

### GitHub Pages

仓库已包含 `.github/workflows/deploy.yml`：推送到 `main` 后，GitHub Actions 会安装依赖、构建 `dist/` 并发布到 Pages，不需要本地提交构建产物。

1. 在 GitHub 新建仓库，把本地 `main` 推上去。
2. 仓库 **Settings → Pages → Build and deployment → Source** 选择 **GitHub Actions**。
3. 推送 `main`，或在 Actions 页面手动运行 **Deploy to GitHub Pages**。
4. 发布地址通常是 `https://<用户名>.github.io/<仓库名>/`；`base: './'` 已经适配仓库子路径，不用再改。

注意：

- 免费账号的 GitHub Pages 只对 **public** 仓库开放；私有仓库需要 GitHub Pro/Team 等支持 Pages 的方案。
- 当前 `dist/` 约 96 MB（主要来自完整音频与反诈视频）。单文件都低于 GitHub 100 MB 限制，站点总量也低于 1 GB，但首次部署和访问会比纯文本站点慢。
- 没有后端、路由或环境变量依赖；部署后可以直接跑 `npm run smoke:public -- https://<用户名>.github.io/<仓库名>/` 做公网冒烟测试。

### 临时发布到公网（隧道）

本项目是纯静态 H5、没有后端，所以任何静态托管都能用。临时演示最省事的做法是打一条隧道：

```bash
# 1) 起预览服务（对外监听，便于隧道回连）
node node_modules/vite/bin/vite.js preview --port 4173 --strictPort --host 0.0.0.0

# 2) 另开一个终端，把 4173 隧道到公网（cloudflared 需自行下载，不要放进仓库）
cloudflared tunnel --url http://127.0.0.1:4173 --no-autoupdate

# 3) 拿到形如 https://xxxx.trycloudflare.com 的地址后，做一次真实浏览器冒烟
npm run smoke:public -- https://xxxx.trycloudflare.com/
```

两个坑已经踩过并修好，重新部署时不必再踩：

1. **`403 Blocked request. This host "..." is not allowed.`**
   这不是 Cloudflare 拦的，是 Vite preview 自己的 Host 校验（防 DNS rebinding）。已在 `vite.config.ts` 的 `preview.allowedHosts` 放行 `.trycloudflare.com` 与 `.loca.lt`。只放行这两个隧道域名，本机与局域网访问照旧，陌生 Host 仍然返回 403（可实测验证）。
2. **`EPERM: unlink '...cloudflared.exe'`**
   `verify-edge.mjs` 原先会整目录删掉 `.verify/`，一旦里面放了对外的隧道程序（进程占用文件）就会直接把验证跑崩。现在只清理脚本自己产出的截图/profile/report。另外隧道程序属于本机工具，建议放在仓库外（例如 `E:\DSH\_fj-tunnel\`），不要放进工作区。
3. **隧道预览服务占着 4173 时，`npm run verify` 会跑错对象（2026-10-16 修）**
   上面第 1 步起的隧道服务用的就是 4173，与 verify 默认端口相同。端口被占时 verify 自己的服务因 `--strictPort` 起不来，而 `waitForHttp` 却因为**别人的**服务在监听而通过 —— 整个验证悄悄跑在另一个进程上，最后「预览服务已释放」必然失败，报错信息还完全指不到真正的原因。
   现在 verify 会先探测端口，被占用就自动改用下一个空闲端口（会打印一行提示），并把「服务已释放」的断言限定为**本脚本自己起的那个端口**。也可以用 `VERIFY_PORT` 显式指定。**开着隧道预览时直接跑 `npm run verify` 现在是安全的。**

临时隧道地址的注意点：

- **开关都在本机，不进仓库**：关闭外网访问只要结束 `cloudflared` 进程（`Stop-Process -Name cloudflared -Force`），本地与局域网预览不受影响；关闭后公网地址返回 HTTP 530 属正常。关闭状态下 `preview.allowedHosts` 里的白名单不产生任何影响，因为没有任何进程在监听那个 Host。
- **地址是临时的**：cloudflared quick tunnel 每次重启都会换一个新域名，且官方明确不保证可用性（无账号隧道仅供试用）。
- **任何人拿到链接都能玩**：游戏不接后端、不上传玩家选择，除玩家本机 `localStorage` 外无数据落地。
- **延迟偏高**：实测出口落在 Cloudflare 圣何塞（sjc），单次资源请求约 1–1.7 秒；首屏可见约 5 秒。功能正常，但不如局域网地址流畅。局域网试玩仍推荐 `http://<本机IP>:4173/`。

```text
src/

  app/LevelDesk.vue      # 关卡大厅（当前主版本）：书桌场景 + 旋转放大转场
  app/DeskPhone.vue      # 书桌上的「一部手机」（card = 卡片；screen = 飞行层用）
  app/levelCardText.ts   # 关卡卡片的文案推导（纯函数：状态/行动/无障碍标签）
  app/PhoneShell.vue     # 一部手机（= 一个关卡）：状态栏 + 应用视口 + 底部导航 + 弹层
  app/navigation.ts      # UI 导航状态与「节点 → 场景」的通用映射，不含剧情与金额

  app/settings.ts        # 版本化玩家设置（音效、顶部提醒开关、壁纸）
  app/sound.ts           # Web Audio 合成音效（无音频文件，失败静默降级）
  app/chatReveal.ts      # 会话「逐条出现」的进度记忆（按关卡 + 会话区分）
  app/useGame.ts         # 组合式封装：dispatch 是唯一写入口，负责存档（每关一个实例）
  game/level.ts          # 关卡契约：defineLevel / validateLevel / collectLevelText
  game/types.ts          # 节点、选项、状态、效果类型
  game/engine.ts         # choose() 事务式转移、不变式校验、结局视图（按 state.levelId 解析）
  game/debrief.ts        # 按经历生成复盘 + 肯定式误导表述检查
  game/storage.ts        # 每关一个版本化 localStorage 槽 + v1 迁移，校验失败安全回退
  data/levels/           # 关卡数据：shared + level01 + level02 + level03 + index（注册表）
  data/antifraud.ts      # 「国家反诈中心提醒您」的取用方式（正文在各关 reminders 里）
  scenes/                # Intro / Home / Chat / Wallet / Manual / Ending / Review / PlainApp
  components/            # 状态栏、底部导航、应用标题栏、弹层、气泡、模拟声明、应用图标
  styles/                # 设计令牌与基础样式（含 prefers-reduced-motion）
tests/                   # engine / storage / debrief / clock / unlock / settings /
                         # notifications / levels（关卡守卫）/ tokens / app 十套测试
scripts/verify-edge.mjs  # Edge headless + CDP 端到端验证
scripts/smoke-public.mjs # 公网地址冒烟测试（隧道/静态托管发布后跑）
```

**关卡数据位置**：`src/data/levels/`（每关一个文件：节点、选项转移表、金额常量、会话与话术、复盘规则、提醒、界面文案），注册表在 `src/data/levels/index.ts`。状态转移逻辑在 `src/game/engine.ts`。

**新增一关**：在 `src/data/levels/` 建一个 `levelNN.ts` 并在注册表登记即可 —— 引擎、存档、复盘、导航与场景组件都不需要改；`tests/levels.spec.ts` 会对新关卡自动跑结构、可达性、金额与文案守卫。
