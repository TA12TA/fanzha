# 反诈局中局：你的手机

面向大学生的竖屏 H5 反诈互动游戏。**产品形态：整个网页模拟一部可自由探索的虚构手机**；手机端直接铺满可见网页，开场、桌面、消息、钱包、结局及复盘都在手机内进行。玩家可以随时切换应用、查看余额和手册，再返回当前剧情，不强制困在对话中；电脑端居中预览同一画面。

当前状态：**多关卡结构，三关可玩**（Vue 3 + Vite + TypeScript）。

- **第一关「刷单返利」**：剧情引擎、整页手机界面、按经历复盘与版本化存档已完成。
- **第二关「冒充客服退款」**：完整可玩，金额口径 800 → 600 → 300。
- **关卡大厅**：一关一部手机，玩家自行选择；每关进度各自保留。首次进入先展示作品封面与玩法说明。当前采用**书桌版**：三台手机平放在墨绿桌垫上，点一部就**旋转放大覆盖全屏**进入那一关。轮播版已归档在 git 历史中。
- **手机必备与生活应用**：桌面有**电话**（拨号盘/最近通话/通话界面）、**短信**（收件箱/会话/本机回复）两个必备应用，以及**青集商城**（商品/搜索/订单）、**青听音乐**（切歌/播放/进度）、**青影**（抖音式竖屏 feed：上下滑动、点赞/评论/收藏/分享）三个虚构应用；不接真实通话、短信、支付、音乐或视频服务。第二关的订单核验会从聊天切到商城的订单页，当前验证码会出现在短信应用里，银行卡/账户信息放在钱包。
- **移动端保护**：页面锁定视口、禁止下拉刷新；关卡开始后刷新/关闭会弹浏览器离开确认，进度仍由每次操作即时落盘。
- **真实案例**：反诈手册内置 4 条带来源的案例（电商退款/航班理赔/冒充公检法/刷单），来源与原文摘录见 `CASES.md`，游戏内不放外链。
- **第三关「冒充公检法」**：完整可玩，金额口径 800 → 300（资金核查 500）→ 0（保证金 300）。

账号、后端、排行榜均未开发。

## 视觉方向：青屏 · 墨与灯

整体从通用蓝色 SaaS 风改为「墨绿夜色 + 米纸纸面 + 青玉主色 + 朱砂警示 + 黄铜细节」：

- **图标**：统一为哑光色底板 + 米白线性图形，同一个应用在桌面、程序坞、最近任务和通知中心保持同一套颜色。

## 交给开发模型时怎么做

将此仓库作为其工作目录，直接给出以下指令：

> 阅读 `AGENTS.md`、`LEVELS.md`、`LEVEL-01.md`、`LEVEL-02.md`、`DEVELOPMENT.md`、`SCENES.md` 和 `ACCEPTANCE.md`，在仓库根目录实现 Vue 3 + Vite + TypeScript 可玩 H5。整个网页必须呈现为一部可操作的虚构手机：手机端铺满可见区域，先进入桌面，点通知/消息图标可进群，玩家也可随时切到钱包/手册/其他可用区域并返回当前剧情；离开待付款页只暂停、不自动扣款或取消，结局与复盘也在手机内可离开再进入；不要做成网页中嵌一个缩小手机模型或普通答题页。关卡大厅也要在手机壳内（同一状态栏、同一壁纸、底部动作条），不要做成网页里摆一排缩小手机外框。新增关卡按 `LEVELS.md` 走数据驱动，不要改引擎、存档、导航与场景组件。完成后运行构建和可用测试，更新本 README 中的真实启动命令、已实现功能与已知限制，逐条报告验收情况。

> 注：上面这段是最初交给开发模型的总要求，其中「关卡大厅也要在手机壳内」对应的是最初的轮播版。后来用户要求改为**书桌版**大厅（几部手机平放在桌上、点一部旋转放大进入），当前主分支即这一版；它是有记录的有意例外 —— 见「关卡大厅（书桌版）」与「已知问题与未完成项」。

## 命令与运行方式

```bash
npm install          # 安装依赖
npm run dev          # 本地开发（http://127.0.0.1:5173/）
npm run build        # 生产构建，输出 dist/
npm run preview      # 预览构建产物（http://127.0.0.1:4173/）
npm run typecheck    # vue-tsc 类型检查
npm test             # 单元 + 集成测试（vitest）
npm run verify       # 真实浏览器（Edge/Chrome headless）端到端验证，产出截图与报告
npm run smoke:public -- <公网URL>   # 公网部署冒烟测试：真实浏览器打开公网地址，确认能玩
```

部署：`vite.config.ts` 使用 `base: './'` 相对路径，`dist/` 可直接放到任意静态目录（含子路径）。核心剧情不依赖任何外部服务。

### 临时发布到公网（隧道）

本项目是纯静态 H5、没有后端，所以任何静态托管都能用。临时演示最省事的做法是打一条隧道：

```bash
# 1) 起预览服务（对外监听，便于隧道回连）
node node_modules/vite/bin/vite.js preview --port 4173 --strictPort --host 0.0.0.0

# 2) 另开一个终端，把 4173 隧道到公网（cloudflared 需自行下载，不要放进仓库）
cloudflared tunnel --url http://127.0.0.1:4173 --no-autoupdate

# 3) 拿到形如 https://xxxx.trycloudflare.com 的地址后，做一次真实浏览器冒烟
npm run smoke:public -- https://xxxx.trycloudflare.com/
```

两个坑已经踩过并修好，重新部署时不必再踩：

1. **`403 Blocked request. This host "..." is not allowed.`**
   这不是 Cloudflare 拦的，是 Vite preview 自己的 Host 校验（防 DNS rebinding）。已在 `vite.config.ts` 的 `preview.allowedHosts` 放行 `.trycloudflare.com` 与 `.loca.lt`。只放行这两个隧道域名，本机与局域网访问照旧，陌生 Host 仍然返回 403（可实测验证）。
2. **`EPERM: unlink '...cloudflared.exe'`**
   `verify-edge.mjs` 原先会整目录删掉 `.verify/`，一旦里面放了对外的隧道程序（进程占用文件）就会直接把验证跑崩。现在只清理脚本自己产出的截图/profile/report。另外隧道程序属于本机工具，建议放在仓库外（例如 `E:\DSH\_fj-tunnel\`），不要放进工作区。
3. **隧道预览服务占着 4173 时，`npm run verify` 会跑错对象（2026-10-16 修）**
   上面第 1 步起的隧道服务用的就是 4173，与 verify 默认端口相同。端口被占时 verify 自己的服务因 `--strictPort` 起不来，而 `waitForHttp` 却因为**别人的**服务在监听而通过 —— 整个验证悄悄跑在另一个进程上，最后「预览服务已释放」必然失败，报错信息还完全指不到真正的原因。
   现在 verify 会先探测端口，被占用就自动改用下一个空闲端口（会打印一行提示），并把「服务已释放」的断言限定为**本脚本自己起的那个端口**。也可以用 `VERIFY_PORT` 显式指定。**开着隧道预览时直接跑 `npm run verify` 现在是安全的。**

临时隧道地址的注意点：

- **开关都在本机，不进仓库**：关闭外网访问只要结束 `cloudflared` 进程（`Stop-Process -Name cloudflared -Force`），本地与局域网预览不受影响；关闭后公网地址返回 HTTP 530 属正常。关闭状态下 `preview.allowedHosts` 里的白名单不产生任何影响，因为没有任何进程在监听那个 Host。
- **地址是临时的**：cloudflared quick tunnel 每次重启都会换一个新域名，且官方明确不保证可用性（无账号隧道仅供试用）。
- **任何人拿到链接都能玩**：游戏不接后端、不上传玩家选择，除玩家本机 `localStorage` 外无数据落地。
- **延迟偏高**：实测出口落在 Cloudflare 圣何塞（sjc），单次资源请求约 1–1.7 秒；首屏可见约 5 秒。功能正常，但不如局域网地址流畅。局域网试玩仍推荐 `http://<本机IP>:4173/`。

## 已实现功能与测试结果

### 班级通知群更热闹、且每次不一样（2026-10-17 新增）

用户要求：「班级群通知多一点，随机一点，比如通知反诈的新闻这些」。

- 班级通知群原来只有辅导员的一条教材通知。现在固定保留 3 条（教材通知 + 班长 + 同学闲聊，
  群才立得住），再追加 **3–5 条随机反诈通知** —— 从 `CLASSGROUP_NEWS` 池子里抽，
  池子里是辅导员/班长转发提醒、同学随口一提的那种话（快递理赔、验证码、屏幕共享、
  刷单垫钱、退税、收款码等）。
- **每关只抽一次并缓存**（`app/classNews.ts`）：切到别的应用再回来还是同一批，
  一进一出就换一批会让"群消息"立刻露馅；重新打开页面、或「重新开始本局」才换一批。
- **随机是可复现的**（`app/random.ts`）：浏览器启动时用时间戳播种，所以每局打开都不一样；
  测试拿到的是固定默认种子，断言不会随机变红。这也是这里不用 `Math.random()` 的原因。
- 数据驱动：会话规格里 `newsSession: 'classgroup'` 一行就能挂上（写法见 `LEVELS.md` §2.3），
  加内容只需往池子里加一条。

### 反诈提示改成「国家反诈中心」弹窗（2026-10-17 新增）

用户要求：像「页面上的退款进度不是你的余额。验证码给出去，等于把账户交出去。」
这种形式的提示，做到国家反诈中心的**弹窗**里去，并且提示第一行应该是
「检测到你疑似被诈骗」这类**说明原因**的话。

- 新增 `components/AntiFraudDialog.vue`：模态居中卡片 —— 标题「国家反诈中心」、
  **第一行是判断**「检测到你疑似正在被诈骗」、正文是判断依据、底部「我知道了」。
  自绘盾牌图标，不用任何官方徽标；Esc 也能关，键盘用户不会被卡住。
- 那句宣导从**聊天气泡**搬进了弹窗（第二关 `l2-refund-claim` 的提醒文案就是它），
  同一条内容不再在两个地方各说一遍。
- **不是所有节点都弹窗**：由关卡数据 `popupReminders` 声明。目前第一关的三个**掏钱时刻**
  （首次垫付 / 解冻费 / 追加垫付）、第二关的**索要验证码**，以及第三关的首次联系和两笔转账。
  弹窗会打断操作，每个节点都弹，玩家就开始无脑点「知道了」，等于没弹 —— 其余节点仍是顶部横幅。
  第三关首次联系的弹窗由 `deferredPopupNodes` 延迟到玩家点开来电通知/进入会话后才出现，
  不会在刚解锁桌面时提前弹。
- **转账弹窗有倒计时**：第三关的两笔转账提醒由 `popupCountdowns` 声明 3 秒倒计时，
  倒计时结束前「知道了」是 disabled 的，避免玩家条件反射地点掉；写法见 `LEVELS.md`。
- 无论弹窗还是横幅，都会记进通知中心，随时回看；仍受「顶部弹出通知」开关控制。

### 模拟验证码（2026-10-17 新增）

第二关「冒充客服退款」在「把短信验证码发我」这一步，原本只有一个「继续按他说的做」按钮 ——
玩家点一下就过去了，等于什么都没学。现在这一步真的做出来了：

- **短信真的会来**：以通知形式从顶部弹出，发送方是虚构品牌「安心钱包」，
  正文含 6 位验证码。验证码**本地随机生成**，每次索要都不同（含输错重发）；
  不读真实短信、不申请任何权限、不上传。
- **必须填回去**：聊天底部出现验证码输入区（真实 `<input>`，`inputmode="numeric"`，只收数字），
  「继续按他说的做」按钮不再渲染 —— 不填就走不了这一步。
- **输了会重发**：对方平和地再说一句「好像不太对哦，你再看一下刚刚那条短信？
  我这边再发一条新的给你」，并换一个新验证码。语气刻意不施压：
  现实中的骗子在这一步很有耐心，恐吓是后面要钱时才用的。
- **永远走得下去**：漏看短信可以点「重新发一条」；「顶部弹出通知」开关关掉时，

### 音效约定

| 场景 | 音效 |
| --- | --- |
| 导航、打开/关闭界面、普通按钮 | `tap` |
| 破坏性或丢弃类操作（清掉重来、清空） | `cancel` |
| 剧情里的确认付款 | `confirm` |
| 剧情里的拒绝/退出 | `cancel` |
| 通知弹出（预警 / 消息） | `alert` / `receive` |
| 解锁 | `unlock` |

原则：**玩家的每一次有意操作都要有反馈，但自动发生的事（通知到时自动关闭）不该补音效** —— 否则手动关闭与自动关闭会听起来一样，玩家分不清自己点没点上。
